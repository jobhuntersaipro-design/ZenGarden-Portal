# Loving Hands Portal — UI change brief for Claude

Use this document to improve the Loving Hands Portal web UI at https://www.lovinghandsportal.com  
Source: live walkthrough signed in as Aisha Rahman (2026-09-06), Critiquito design review.

**Product context:** Web ops portal for purchase-order intake and fulfillment. Primary users live in the tool daily. Currency MYR (RM). App chrome: sidebar (Dashboard, Purchase orders, Buyers, Products) + header `Upload PO` CTA.

**User-reported pain (confirmed in review):**
1. Feels laggy / unresponsive
2. Missing loading animation
3. Missing back button

**Rules for you (Claude):**
- Prefer concrete UI/UX changes over vague advice.
- Do not invent new product modules.
- Keep working patterns listed under “Do not break.”
- Apply shared patterns (loading, back, truncation) on every screen that shares the chrome.
- Severity: **Must** = ship-blocking for perceived quality; **Should** = clear cost; **Nice** = polish.

---

## Do not break

- Sidebar destinations: Dashboard, Purchase orders, Buyers, Products (Upload is a CTA, not a peer nav item — keep that).
- PO detail lifecycle stepper (6 stages) + Advance action + activity log.
- Status / stage breakdown bars and text labels with color (never color alone).
- Upload drop zone accepting PDF / PNG / JPG up to 20 MB.
- Sign-in pending label (`Signing in…`) — this pattern is good; extend it elsewhere.

---

## Root cause of “laggy”

Observed behavior: list/dashboard screens **paint incomplete metrics first**, then **silently revise** counts and RM totals (e.g. Dashboard 13 POs / RM254k → 38 / RM737k; Buyers 2 → 11; Products 11 → 12) **with no spinner, skeleton, or “Updating…” state**.

Users experience that as lag or broken UI: numbers jump, charts reflow, and nothing explains the wait.

**Fix strategy (global):** treat every async data region as either (a) skeleton while pending, or (b) stale-with-overlay while refreshing — never blank-then-jump and never final-looking numbers that still change.

## Global / cross-cutting

### G1. Loading system — **Must** (addresses lag + missing loading animation)

**Add one shared loading language:**

| Situation | Pattern |
|-----------|---------|
| First load of a page/section | Skeleton placeholders matching final layout (KPI cards, chart block, table rows) — not a blank white main area |
| In-place refresh (filter/date change) | Keep previous content at reduced opacity **or** show a small top progress bar + `Updating…` in the summary line; disable conflicting controls until settle |
| Button that waits on network | Disable button + pending label (reuse Sign-in: `Signing in…`) e.g. `Uploading…`, `Saving…`, `Advancing…` |
| Row / card navigation to detail | Optional full-page route transition: thin top progress bar (nprogress-style) OR detail shell with skeletons |
| File upload | Per-file progress bar + status text (Uploading / Extracting / Failed) — reserve UI space even before first file |

**Acceptance:**
- No KPI/table/chart region appears “final” while a request is still in flight.
- Filter changes never silently rewrite headline numbers without a visible updating state.
- At least one obvious motion/indicator exists within ~100ms of navigation or filter change.

**Implementation notes:**
- Prefer skeletons over a centered spinner for Dashboard / lists (spinner alone still feels laggy on dense pages).
- If using React Query / SWR / similar: drive skeletons from `isLoading` / `isFetching`; show `isFetching` indicator even when cached data is shown.
- Avoid blocking the whole app shell; keep sidebar interactive.

### G2. Back navigation — **Must** (addresses missing back button)

**Problem:** Detail views only expose a text breadcrumb (`Purchase orders / PO-…`). Upload uses `Cancel`. No consistent, discoverable Back control. Many ops users expect an explicit back control especially after deep scrolls.

**Change:**
1. On **every detail / secondary screen**, add a clear control above the title:
   - Icon + label: `← Back` (or `← Purchase orders` when return target is unambiguous)
2. Place it **left of or directly above** the breadcrumb; clicking returns to the list (same as breadcrumb parent).
3. Screens that need this:
   - PO detail
   - Buyer detail
   - Product detail
   - Upload (`Cancel` → rename/promote to `← Back` **or** keep Cancel and add Back that goes to previous route / Purchase orders)
4. Keep breadcrumbs; Back is additive, not a replacement.
5. Use `history.back()` only when referrer is in-app; otherwise navigate to the section list route (safer for deep links).

**Acceptance:** From any detail or Upload screen, a user can return with one click on a control that looks like Back — without using the browser chrome.

### G3. Truncation — **Should**

**Problem:** Truncated strings with no recovery: sidebar email `aisha@lovinghandspor…`, Dashboard Top buyer `Northwind Tr…`, product names, dense table columns clipped at edges.

**Change:**
- Truncate visually in tight cells; full value on **hover tooltip** and when focused.
- Sidebar: wrap email to two lines **or** show full email in tooltip; never dead-end ellipsis as the only form.
- KPI “Top buyer”: allow wrap to 2 lines or show full name under the RM line.

### G4. Label contrast — **Should**

**Problem:** Small muted gray labels (`Overview`, field labels, helper text) look low-contrast on white.

**Change:** Darken secondary text to meet ~4.5:1 for text under ~14px (use your design tokens; e.g. move from ~gray-400 to gray-600/700). Keep decorative eyebrows lighter only if ≥12px and still ≥3:1.

### G5. Table density / horizontal clip — **Should**

**Problem:** Wide tables clip columns (e.g. PO total on product order history). Hard to scan.

**Change:**
- Ensure horizontal scroll **inside** the table card with a visible scroll affordance, **or** drop/combine lower-priority columns at this breakpoint.
- Sticky first column (PO number) when horizontal scrolling.
- Align numeric columns (Qty, prices, totals) to the right with consistent tabular lining.

### G6. Line-item cell spacing (PO detail) — **Must**

**Problem:** Qty and unit price run together visually (`4 kitRM 3,428.15`).

**Change:** Separate columns clearly; format as `4 kit` | `RM 3,428.15` with padding; never concatenate unit into the currency string.

## Screen-by-screen

### 1. Sign in — **Nice**
**Keep** disabled `Signing in…` pending state (good reference for G1).  
Optional: add subtle logo/card skeleton only if post-login redirect is slow (>2s).

### 2. Dashboard `/` — **Must**
**Loading:** On first paint and on filter/aggregate change, skeleton the KPI row + chart + table (G1). Never show temporary wrong PO counts/RM then swap silently.

**Hierarchy (Should):** Lead attention to intake work in Status breakdown (Needs review / Extracting / Failed) — make those counts clickable filters into Purchase orders or Review queue. Chart can stay, but work counts should not feel secondary to vanity KPIs.

**Truncation:** Fix Top buyer (G3).

### 3. Purchase orders list `/purchase-orders` — **Should**
- Skeleton table rows on first load / filter change (G1).
- Status chips: show counts when >0 (Needs review, Failed, etc.).
- Preserve search + filters; ensure filter apply shows updating state.

### 4. PO detail `/purchase-orders/:id` — **Must**
- Add **Back** (G2); keep breadcrumb.
- Loading: detail shell skeletons for lifecycle + summary + lines while fetching.
- **Original document error:** “We couldn't read that PDF…” — improve:
  - Keep the message
  - Add secondary action: `Download original` (already in header — also place next to the error)
  - Optional retry: `Try preview again`
- Fix line-item spacing (G6).
- Advance button: pending state `Advancing…` while request runs; disable double-submit.

### 5. Buyers list `/buyers` — **Must**
- Same async metric jump issue → skeletons / updating state (G1).
- KPI + attention summary should not flash wrong totals.

### 6. Buyer detail `/buyers/:id` — **Must**
- Add **Back** (G2).
- Long page: consider sticky header with Back + buyer name while scrolling.
- Chart/filter changes use G1 refresh pattern.

### 7. Products list `/products` — **Must**
- Skeleton grid cards on load/filter (G1).
- Stop silent 11→12 / revenue jumps without feedback.

### 8. Product detail `/products/:id` — **Must**
- Add **Back** (G2).
- **Broken images:** main + thumbnails show alt-only gray boxes.
  - Show proper empty/error tile: icon + `Image unavailable` + `Replace image` (if permitted) or hide empty thumbnails
  - Don’t leave raw alt text as the only visible content in a large hero
- Order history table: fix clipped columns (G5).

### 9. Upload `/upload` — **Must**
- Replace or supplement `Cancel` with clear **← Back** to Purchase orders or previous page (G2).
- **Before any file:** show an empty queue region caption, e.g. `No files yet` — so the post-upload UI doesn’t pop in layout-shifting.
- **After files selected:**
  - Per-file row: name, size, progress bar, status (`Uploading` / `Extracting` / `Ready` / `Failed`)
  - Disable Browse or allow multi-add intentionally
  - Primary action when ready: `Review N files` (if review exists) or `Done`
- Animate progress (determinate if % known; otherwise indeterminate bar). This is the loading animation users expect on this screen.

### 10. Account menu — **Nice**
- Currently only `Sign out`. Fine.
- Optional: Account / Profile link later — out of scope unless requested.
- Sidebar email truncation (G3).

## Copy / microcopy

| Location | Change |
|----------|--------|
| Async refresh | Summary line may show `Updating…` while `isFetching` |
| PDF preview fail | Keep error; add `Download original` beside it |
| Product image fail | `Image unavailable` instead of raw alt text filling the hero |
| Upload empty | `No files yet — drop POs above` |
| Upload Cancel | Prefer `← Back` or pair Cancel with Back |
| Advance | Pending: `Advancing…` |

## Test plan (manual)

1. Hard-refresh Dashboard on slow 3G throttle: skeletons appear; final numbers show once; no mid-flight “final” wrong totals.
2. Change Last 30 days → Last year: visible Updating state; no silent jump.
3. Open PO detail from list: Back returns to list; breadcrumb still works.
4. Open Upload: Back/Cancel returns; drop a PDF: progress bar visible; no layout jump from empty→queue.
5. Open product with broken images: friendly empty state, not alt-text soup.
6. PO with bad PDF preview: error + Download original reachable without hunting header only.
7. Confirm line items read as separate Qty and Unit price cells.
